# DocFlow M3 运行成本与延迟诊断报告

日期：2026-09-04

云端验收提交：`396e5ab`

模型：`deepseek-v4-flash`（OpenAI-compatible Chat Completions）

## 目标与口径

M3 不评价“模型回答是否优于规则”，而是补齐单次 Run 和当前访客 Session 的运行证据：

- 任务执行成功、失败、降级与重试；
- 总耗时和模型耗时 P50/P95；
- Planner 与内容理解两个模型阶段的调用状态、耗时和 Token；
- 输入缓存命中/未命中 Token 与可选成本估算；
- 引用、内容、工具和人工审核门禁。

统计范围只包含当前访客 Session 的 SQLite 任务历史。固定诊断阈值不是生产 SLA，单次验收也不是生产稳定性结论。

## 实现

- 模型调用记录提供方、模型名、请求 ID、阶段、成功状态、耗时与 Usage；不记录 API Key。
- DeepSeek 返回缓存拆分字段时，分别使用 `prompt_cache_hit_tokens` 与 `prompt_cache_miss_tokens`；字段缺失时不会假设缓存比例。
- 只有输入与输出费率完整配置时才估算成本，否则明确显示“未配置单价”。
- 费率配置保留版本标签。本次采用 DeepSeek V4 Flash 的美元峰值费率作为保守上限：缓存命中 0.014、缓存未命中 0.44、输出 1.32 美元/百万 Token。实际账单可能因时段和提供方调价而不同，价格以 [DeepSeek 官方价格页](https://api-docs.deepseek.com/quick_start/pricing/) 为准。
- 诊断接口按模型、规则和规则降级路径分组，并单独展示 Planner/内容理解阶段。

## 首次云端验收发现的问题

首次部署 `deepseek-v4-flash` 后，强制验收返回 `TimeoutError`。原因不是密钥或网络不可达，而是 DeepSeek V4 默认开启高强度思考；DocFlow 原请求没有显式关闭思考模式，两个结构化 JSON 阶段超过 20 秒/40 秒边界。

修复方式：

- Planner 和内容理解请求显式设置 `thinking.type=disabled`；
- Planner 最大输出限制为 1,200 Token，内容理解限制为 3,000 Token；
- 保留原有本地 SafePlanner、Evidence、Verifier 和人工审核门禁；
- 新增自动化断言，确保两个阶段都携带非思考模式与输出上限。

该选择符合任务边界：这两个阶段是受证据约束的结构化提取与规划，不需要长链路自由推理。DeepSeek 对默认思考模式及关闭参数的说明见 [官方思考模式文档](https://api-docs.deepseek.com/guides/thinking_mode/)。

## 仍然存在的边界

- 当前数据是固定合成回归与一次云端强制验收，不是生产准确率、SLA 或长期成本分布。
- 成本是按配置的峰值费率计算的上限估算，不等于 DeepSeek 账单。
- 当前没有真实用户量、人工修改率、业务节省时间或盲评偏好数据；这些属于 M4 小规模真实用户试用范围。
- 模型失败时仍允许显式降级到规则路径；诊断页会把降级单独统计，不能把该结果表述为模型输出。
