# DocFlow 真实模型运行验收（2026-09-04）

## 验收目标

验证云端 DocFlow 确实经过 OpenAI-compatible 模型路径，同时保留 Evidence、负责人、截止时间、Verifier 和 Human Review 约束。该记录是小样本部署验收，不是生产准确率或 SLA。

## 环境与口径

- 云端配置：`MODEL_BASE_URL=https://api.deepseek.com/v1`、`MODEL_NAME=deepseek-chat`。
- 提供方响应记录的实际模型名：`deepseek-v4-flash`。
- 每次任务包含独立 Planner 与内容生成调用，并记录提供方 Request ID、Token 和模型耗时。
- 验收材料使用内置周报模板，显式包含风险负责人李明、截止时间周五前，以及行动负责人王芳、截止时间下周二。
- 严格脚本要求模型路径完整、引用可映射、内容质量通过、审核前导出返回 409、审核后导出成功。

## 回测发现与修复

增强验收首次运行时，模型将“周五前”缩写为“周五”。引用仍存在，但显式时间约束发生变化，Verifier 正确返回 `content_quality_passed=false`。

修复后，模型仍可改写风险描述和组织结构，但同一 Evidence 中显式标注的负责人和截止时间会恢复为原始值；Verifier 规则没有放宽。对应修复提交为 `1b0d49b`。

## 其他验证

- 本地自动化测试：82/82 通过。
- 固定合成规则评测：20/20 通过；该结果仅代表固定集合。
- 公网入口：未认证返回 HTTP 401，认证后首页和 `/ready` 返回 HTTP 200。
- 模型超时与网络失败通过自动化测试验证会标记为 `rules_fallback`，界面不得继续宣称模型生成。
